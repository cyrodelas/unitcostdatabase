# ML Governance Foundation

Phase 24 provides governed data preparation. Phase 25 may invoke a separately registered active Extraction model through the configured private service, but it still does not train, evaluate, register, activate, or roll back models through the UI.

## Dataset lifecycle

1. An `ml.train` user creates an Extraction, Mapping, or Resource Template dataset.
2. Creating a version snapshots eligible authoritative records at one cutoff timestamp. Payload and label JSON plus a record SHA-256 are stored immutably.
3. An `ml.review` user approves, rejects, or reopens each label. Every action appends `ml_feedback` history.
4. A version can freeze only when no labels are pending and at least one is approved. Freeze calculates the manifest checksum and queues an idempotent export job.
5. An operator runs `php index.php ml_worker run`. The CLI worker claims one queued export, writes only approved records to JSONL outside the web root, calculates its SHA-256, and records the result.
6. An `ml.review` user may approve only a frozen version with a successful checksum-recorded export. Approved versions are immutable.

Empty versions cannot freeze. Rejected labels remain in review history but are excluded from exports.

## Snapshot sources

- Extraction: Valid or Imported BOQ staging rows, grouped by import batch to prevent workbook leakage across future train/test splits.
- Mapping: Confirmed selections as positive labels and rejected selections as hard negatives, grouped by BOQ item and targeting the stable cost-item identity.
- Resource Template: Approved or Published revision definitions and their materials, labor, equipment, and allowances, grouped by stable cost item.

Source identifiers are lineage references rather than foreign keys because the snapshot JSON and checksum must remain reproducible even if a separately authorized source deletion occurs later.

## Artifact storage

Set `UCD_ML_ARTIFACT_PATH` to an absolute directory outside the web root. The current safe default is `C:\xampp\nexus_ucd_ml_artifacts`. The browser never accepts an artifact path or executable upload and exposes no artifact-download route.

Exports contain a manifest header followed by canonical approved records. Artifact file names are generated by the worker from database identifiers and the manifest checksum.

## Permissions

- `ml.view`: view datasets, review state, jobs, and read-only registry metadata.
- `ml.review`: review labels and approve checksum-verified dataset versions.
- `ml.train`: create datasets/versions and freeze/queue exports. It does not run training in Phase 24.
- `ml.deploy`: reserved for Phase 27 model approval, activation, and rollback; no Phase 24 endpoint uses it.

Model registry and training/evaluation job fields remain governance foundations. Phase 25 reads an already active Extraction model for reviewed shadow assistance only; no deployment action was added.
